# Security Policy

## Reporting a vulnerability

Do not open a public GitHub Issue for suspected vulnerabilities, credentials,
exploitable behavior, or sensitive security evidence.

Use the repository's private vulnerability reporting channel under the GitHub
**Security** tab when enabled. Template adopters must configure a private contact
or GitHub Private Vulnerability Reporting before public launch and document it
here.

If no private channel is visible, contact the repository owner through an
already-published private security contact. Do not send secrets or exploit data
to an unverified address.

Ordinary planned product work may use the `risk:security` label. That label does
not replace the private vulnerability disclosure process.
